# 角色 Bot 作息与离线信箱插件

面向 AstrBot + NapCat（OneBot v11）的角色作息插件。插件会为每个 Bot 生成并持久化每日随机作息，在角色离线时阻止新的 LLM 请求、发送固定监测器提示，并在角色回来后处理离线信箱。

## 兼容性

- AstrBot `>= 4.24.0`
- 消息平台：`aiocqhttp`（NapCat / OneBot v11）
- Python 标准库，无额外依赖
- 需要已经配置可用的聊天模型和角色人格

插件使用 `TextPart.mark_as_temp()` 注入仅限本轮的私聊预告要求，因此不支持低于 4.24.0 的 AstrBot。

## 主要行为

- 每天随机生成起床、睡觉及一至多段白天临时离开。
- 睡觉区间允许跨午夜，夜间睡眠不占白天离开总量。
- 同一天的计划、原因和固定监测器文案一经生成便写入 SQLite，重启不重新抽取。
- 离开前只处理最近活跃的私聊。若预告期内正好发生正常回复，就把一次性预告要求附在该回复中；否则在等待一段时间后单独生成一句预告。
- 离线时只拦截 AstrBot 已认定为唤醒的消息，即 `event.is_at_or_wake_command`。唤醒词、@、私聊及框架认定的等价唤醒方式均跟随 AstrBot 自身设置。
- 每条离线唤醒消息都会立即收到同一离线段固定的监测器提示，不调用 LLM，也没有冷却。
- 普通群消息继续传播，并继续供 AstrBot 自带群聊上下文功能使用。
- 群聊回归先按消息总量抽样，再按发送者合并。同一个群聊窗口的一批回归只调用一次 LLM，随后分别引用回复每个用户。
- 私聊不抽样；同一私聊窗口的全部离线消息合并成一次回复，并只在该次请求临时解除人设字数限制。
- 群聊不发送公共“我回来了”广播。没有抽中消息时静默恢复且不调用 LLM。
- 回归回复进入持久化延迟队列；已经生成但尚未发送的回复会在重启后继续发送。

## 安装

1. 在 AstrBot WebUI 确认版本已升级到 4.24.0 或更高。
2. 在插件管理中选择“本地安装”，上传本插件压缩包。
3. 打开插件配置，至少修改 `bot_name`、作息区间、原因和监测器文案。
4. 若要使用指定模型生成预告和回归回复，在 `provider_id` 中选择 Provider；留空则跟随对应会话当前模型。
5. 保存配置并重载插件。
6. 建议在 AstrBot 配置中启用群聊上下文感知，并把群聊记录数量设置在合理范围。插件不会修改全局群聊上下文配置。

管理员可使用 AstrBot 当前唤醒词调用：

```text
/今日作息
/作息状态
```

命令前缀由 AstrBot 处理，不在插件中写死。

## 多 Bot 配置

数据库和运行状态按 `self_id` 隔离。全局配置作为默认值；同一 AstrBot 同时连接多个角色 Bot 时，可在 `bot_profiles` 中按 `bot_id` 覆盖任意同名字段。

示例：

```json
[
  {
    "bot_id": "10001",
    "bot_name": "角色A",
    "wake_window": {"start": "07:00", "end": "08:30"},
    "sleep_window": {"start": "22:30", "end": "00:30"},
    "daytime_away": {
      "total_minutes_min": 20,
      "total_minutes_max": 80
    }
  },
  {
    "bot_id": "10002",
    "bot_name": "角色B",
    "wake_window": {"start": "09:00", "end": "11:00"}
  }
]
```

每个覆盖项未填写的部分继续继承全局配置。`reasons`、`provider_id`、回归抽样和发送延迟也可以按 Bot 覆盖。

## 数据与重启恢复

运行数据目录位于：

```text
data/plugin_data/<插件目录名>/
```

请确保 AstrBot 的 `data` 目录位于 Docker 持久卷中。插件目录内不保存运行数据，升级或重新安装插件不会覆盖 SQLite。

恢复规则：

- 同一天重启继续使用原计划。
- 重启时仍处于离线区间，会恢复原原因和固定监测器文案。
- 已经完成抽样和生成的发送队列不会重新抽样或重新调用 LLM。
- 如果 AstrBot 停机期间某段离线已经完整结束，该段标记为错过，不补演。
- 真正断线期间，QQ/NapCat 没有重放给 AstrBot 的消息无法恢复。

## 群聊上下文说明

离线监听器优先级为 `10000`：

```text
普通群消息
  -> 插件放行
  -> AstrBot 后续处理器和群聊上下文继续工作

离线唤醒消息
  -> 写入插件离线信箱
  -> 发送固定监测器提示
  -> stop_event()
  -> 不进入默认 LLM
```

为了让插件主动调用 `llm_generate()` 时仍有近期环境背景，插件另存少量普通群消息。离线候选消息不会进入这份背景缓存，未抽中的候选不会借此绕过抽样。AstrBot 自带群聊上下文仍保持启用且不受插件修改。

处理器与 AstrBot 内置群聊上下文的真实先后顺序依赖实际安装版本，首次部署必须按下方步骤验证。

## 首次部署验收

建议临时把一个测试 Bot 的起床和离开区间调整到几分钟内，并启用 DEBUG 或 Trace 日志。

1. 在线时在测试群发送普通消息，确认其他插件和 AstrBot 群聊上下文仍正常。
2. 在线时使用唤醒词或 @ Bot，确认正常进入默认 LLM。
3. 进入 `PRE_AWAY` 后在私聊发消息，确认正常回复自然带出一次预告，且下一轮不再携带预告要求。
4. 进入离线后，在群内发送一条普通水聊，确认插件不回复、不停止传播。
5. 离线时连续发送两条 @/唤醒消息，确认每条都立即收到同一条固定监测器提示，日志中没有为监测器调用 LLM。
6. 检查候选消息已落库，并确认它没有触发默认 Agent/LLM。
7. 等待回归，确认群聊没有公共回归语；抽中的用户分别收到 QQ 引用回复。
8. 测试私聊留下多条消息，确认回来后只生成一条合并回复。
9. 在已生成、尚未发送的延迟阶段重启 AstrBot，确认回复队列恢复且没有重新抽样或重新调用模型。
10. 执行 `/今日作息` 和 `/作息状态`，核对时间、原因和当前状态。

如果第 4～6 步表明当前 AstrBot 4.24 补丁版本的内置处理顺序不同，应先停用插件并保留日志，不要修改 AstrBot 核心；调整插件优先级后重新验证。

## 测试

`tests/` 只在开发时由 pytest 读取，不会被 AstrBot 自动执行，也不影响插件运行。

当前测试覆盖：

- 起床和跨午夜睡觉区间
- 白天总时长、分段长度与不重叠
- 同日计划持久化和重启恢复
- 多 Bot 配置覆盖
- 离线候选去重
- 100 条候选、30% 比例、20% 浮动时始终抽取 24～36 条
- 先抽样后按用户合并
- 群聊单次 LLM、按用户拆分引用发送
- 私聊全量合并和一次性长度豁免提示
- 普通群消息放行、离线唤醒消息拦截
- `mark_as_temp()` 的私聊预告注入
- 回归队列持久化

## 已知边界

- 本地开发环境没有运行 AstrBot/NapCat，因此 QQ 主动发送中 `Reply + At + Plain` 的实际显示效果必须在目标 WebUI 部署中验收。
- 模型结构化输出异常时，插件不会把原始 JSON 或提示词发进群；缺失的用户回复会使用短安全回退文本。
- 单个窗口的回归模型调用失败后会记录日志并停止自动重试，避免故障期间反复产生模型费用。
- 回归消息最终发送失败会标记失败并记录日志，不会放出原始模型协议内容。
