# 角色 Bot 作息与离线信箱插件

面向 AstrBot + NapCat（OneBot v11）的角色作息插件。插件会为当前角色生成并持久化每日随机作息，在角色离线时阻止新的 LLM 请求、发送固定监测器提示，并在角色回来后处理离线信箱。配置按“一套 AstrBot 对应一个角色”设计，不提供多角色覆盖入口。

## 兼容性

- AstrBot `>= 4.24.0`
- 消息平台：`aiocqhttp`（NapCat / OneBot v11）
- Python 标准库，无额外依赖
- 需要已经配置可用的聊天模型和角色人格

插件使用 `TextPart.mark_as_temp()` 注入仅限本轮的安排连续性约束，因此不支持低于 4.24.0 的 AstrBot。

## 主要行为

- 每天随机生成起床、睡觉及一至多段白天临时离开。
- 起床时间默认在 08:00～10:00 之间随机，睡觉时间默认在 23:00～次日 01:00 之间随机；两个端点就是明确的浮动范围，可在配置中修改。
- 睡觉区间允许跨午夜，夜间睡眠不占白天离开总量。
- 白天时段可选择“均匀散布”或“自由随机”：前者让各段间隔倾向平均，后者允许离开事件扎堆、连续或集中在一天某部分。
- 白天临时离开默认每日总计 60～120 分钟、1～2 段，单段 30～120 分钟。
- 切换放置算法只影响尚未生成的新日程；同日以及已经提前写入 SQLite 的次日计划不会重抽。
- 同一天的计划、原因和固定监测器文案一经生成便写入 SQLite，重启不重新抽取。
- 作息时间、白天原因池或监测器模板发生变化并重载插件时，会用配置指纹自动重建尚未开始的今天和明天计划；已经开始的离开/睡眠事件及历史记录不会改动。
- 白天原因 JSON 有错误时会在 `/今日作息` 中报告，并停止生成新的白天离开事件，不再偷偷使用兜底池替代错误配置。旧配置完全没有该字段时仍使用内置兜底池，其中休息原因表述为“打盹”。
- 离开前只处理最近 5 分钟活跃的私聊和群聊。预告始终由插件作为一条独立消息发送，不会拼接到正常回复的开头或结尾；同一次离开在同一群聊只预告一次。
- 预告期内的每次私聊都会临时注入安排连续性约束：正常回复不得夹带预告，也不得取消、否认或作出与即将离线相冲突的承诺。
- 独立离开预告和私聊独立回归通知均由代码强制限制为单行且不超过 30 个字符。
- 离线期间在最高优先级静默终止所有未明确唤醒的事件，包括普通消息、单纯引用和戳一戳通知，防止其他低优先级插件绕过作息状态直接调用 LLM。
- 群聊只有“真实 @ 当前 Bot”或“AstrBot 已处理的唤醒词”会收到监测器提示并进入离线信箱；单纯引用不会触发提示。
- “离开或睡眠时仍可使用的指令”是例外白名单，每项只写指令名称。私聊关闭“需要唤醒词”时可直接发送 `查看核心记忆`；私聊开启该设置时遵循 AstrBot 的唤醒判定。群聊仍需使用当前唤醒词，例如当前为 `/` 时放行 `/查看核心记忆`。插件不写死前缀。
- 白名单指令不会收到监测器提示、不会进入离线信箱，也不会被最终 LLM 阻断器二次拦截。默认放行 `查看核心记忆`、`记忆总结`、`查看总结进度`，可在 WebUI 中逐项增删。
- 私聊同一离线事件、同一会话只发送一次固定监测器提示；后续消息仍会进入离线信箱并阻止 LLM，但不会重复刷屏。新的离线事件会重新提示一次。
- 群聊每次真实 @ 或使用唤醒词都会立即收到该离线段固定提示。唤醒词由 AstrBot 处理，插件不写死前缀。
- 普通群消息继续传播，并继续供 AstrBot 自带群聊上下文功能使用。
- 群聊回归先按消息总量抽样，再按发送者合并。同一个群聊窗口的一批回归只调用一次 LLM，随后分别引用回复每个用户。
- 私聊不抽样；回来时先单独发送一句不超过 30 字的回归通知，再用另一条消息集中回应同一私聊窗口的全部离线消息。内容回复只在该次请求临时解除人设字数限制。
- 群聊不发送公共“我回来了”广播。没有抽中消息时静默恢复且不调用 LLM。
- 回归回复进入持久化延迟队列；已经生成但尚未发送的回复会在重启后继续发送。
- 向主动消息插件公开只读的实时可用状态。主动消息只能在“在线”状态发送，不会绕过随机睡眠或白天临时离开。

## 安装

1. 在 AstrBot WebUI 确认版本已升级到 4.24.0 或更高。
2. 在插件管理中选择“本地安装”，上传本插件压缩包。
3. 打开插件配置，按需填写角色名称并修改作息区间、原因和监测器文案；角色名称默认留空。
4. 若要使用指定模型生成预告和回归回复，在 `provider_id` 中选择 Provider；留空则跟随对应会话当前模型。
5. 保存配置并重载插件。
6. 建议在 AstrBot 配置中启用群聊上下文感知，并把群聊记录数量设置在合理范围。插件不会修改全局群聊上下文配置。

所有用户均可使用 AstrBot 当前唤醒词调用：

```text
/今日作息
/作息状态
/调整作息
```

`/今日作息` 中所有时间只精确到分钟。默认只显示日期、起床时间和睡觉时间；开启“在 /今日作息 中显示精确时间表”后，会额外按时间顺序显示每段白天暂时离开的开始时间，不显示结束时间、原因或内部代号。仅当“白天离开原因 JSON”存在语法或条目结构错误时，命令会额外显示错误位置和修正提示。

`/作息状态` 只显示“在线”“暂时离开”或“睡觉”，不公开内部事件代号和起止时间。

`/调整作息` 仅 AstrBot 管理员可用，会立即重抽当前 Bot 在所有私聊和群聊共用的全局未来作息；正在进行的事件不会中断。权限不足时固定回复“只有亲妈才能修改我的作息表……”。该命令在离开和睡眠时也可执行。

命令前缀由 AstrBot 处理，不在插件中写死。

## 离开原因配置

白天离开原因使用普通多行文本框填写 JSON 数组，不加载额外的代码编辑器：

- 每个 `{...}` 是一条原因，复制或删除整段即可增删，数量不设上限。
- 文本框原生支持换行和滚动，不会出现全屏编辑器永久 loading。
- 配置字段使用 `daytime_json`；升级时会避开旧版 `daytime` 的错误模板数据。
- 旧配置缺少原因字段时默认提供“去甜品店”和“打盹”两条，可以删除或修改。
- `id` 可以留空，插件会按当前列表位置自动生成。
- `monitor_messages` 是字符串数组，每个字符串代表一条候选文案。
- 每段离线会随机选择一条文案并固定使用。
- 文案可以包含 `{bot_name}`；角色名称留空时会自动读取当前 Bot 的登录昵称。旧版本已经生成且曾把名称替换为空的日程也会按当前模板恢复显示。

夜间睡眠中的“睡前预告要求（交给 LLM）”不会原样发给用户。它会与当前会话上下文一起交给模型，用来生成一句符合角色人设和双方关系的独立短预告；固定监测器文案仍由代码直接发送，不经过模型。

“夜间睡眠结束后的回归要求（交给 LLM）”只用于整夜睡眠结束后处理睡眠期间收到的消息。插件会把“醒了”等短回归通知单独发送，再另发内容回复；默认要求模型按照完整夜间睡眠后的语义回应，禁止说成“只是打了个盹”或普通暂时离开。这段要求可在 WebUI 修改，不会用于白天临时离开的回归。

## 数据与重启恢复

运行数据目录位于：

```text
data/plugin_data/<插件目录名>/
```

请确保 AstrBot 的 `data` 目录位于 Docker 持久卷中。插件目录内不保存运行数据，升级或重新安装插件不会覆盖 SQLite。

恢复规则：

- 同一天重启继续使用原计划。
- 重启时仍处于离线区间，会恢复原原因和固定监测器文案。
- 已经完成抽样和生成的发送队列不会重新抽样或重新调用 LLM。
- 如果 AstrBot 停机期间某段离线已经完整结束，该段标记为错过，不补演。
- 真正断线期间，QQ/NapCat 没有重放给 AstrBot 的消息无法恢复。

## 群聊上下文说明

离线监听器优先级为 `10000`：

```text
普通群消息
  -> 插件放行
  -> AstrBot 后续处理器和群聊上下文继续工作

离线唤醒消息
  -> 写入插件离线信箱
  -> 发送固定监测器提示
  -> stop_event()
  -> 不进入默认 LLM
```

为了让插件主动调用 `llm_generate()` 时仍有近期环境背景，插件另存少量普通群消息。离线候选消息不会进入这份背景缓存，未抽中的候选不会借此绕过抽样。AstrBot 自带群聊上下文仍保持启用且不受插件修改。

处理器与 AstrBot 内置群聊上下文的真实先后顺序依赖实际安装版本，首次部署必须按下方步骤验证。

## 首次部署验收

建议临时把一个测试 Bot 的起床和离开区间调整到几分钟内，并启用 DEBUG 或 Trace 日志。

1. 在线时在测试群发送普通消息，确认其他插件和 AstrBot 群聊上下文仍正常。
2. 在线时使用唤醒词或 @ Bot，确认正常进入默认 LLM。
3. 进入 `PRE_AWAY` 后在私聊发消息，确认正常回复不夹带预告，插件另发一条不超过 30 字的预告；群聊只有最近 5 分钟活跃时才预告，且同次离开每群一次。
4. 进入离线后，在群内发送一条普通水聊，确认插件不回复、不停止传播。
5. 离线时连续发送两条 @/唤醒消息，确认每条都立即收到同一条固定监测器提示，日志中没有为监测器调用 LLM。
6. 检查候选消息已落库，并确认它没有触发默认 Agent/LLM。
7. 等待回归，确认群聊没有公共回归语；抽中的用户分别收到 QQ 引用回复。
8. 测试私聊留下多条消息，确认回来后先收到独立短回归通知，再收到一条合并内容回复。
9. 在已生成、尚未发送的延迟阶段重启 AstrBot，确认回复队列恢复且没有重新抽样或重新调用模型。
10. 执行 `/今日作息` 和 `/作息状态`，核对时间、原因和当前状态。

如果第 4～6 步表明当前 AstrBot 4.24 补丁版本的内置处理顺序不同，应先停用插件并保留日志，不要修改 AstrBot 核心；调整插件优先级后重新验证。

## 测试

`tests/` 只在开发时由 pytest 读取，不会被 AstrBot 自动执行，也不影响插件运行。

当前测试覆盖：

- 起床和跨午夜睡觉区间
- 白天总时长、分段长度与不重叠
- 同日计划持久化和重启恢复
- 配置默认值与离开原因 JSON 列表解析
- 离线候选去重
- 100 条候选、30% 比例、20% 浮动时始终抽取 24～36 条
- 先抽样后按用户合并
- 群聊单次 LLM、按用户拆分引用发送
- 私聊全量合并和一次性长度豁免提示
- 普通群消息放行、离线唤醒消息拦截
- `mark_as_temp()` 的私聊安排连续性约束与预告独立发送
- 私聊、群聊 5 分钟活跃窗口及同次离开去重
- 独立预告和回归通知的 30 字代码上限
- 回归队列持久化

## 已知边界

- 本地开发环境没有运行 AstrBot/NapCat，因此 QQ 主动发送中 `Reply + At + Plain` 的实际显示效果必须在目标 WebUI 部署中验收。
- 模型结构化输出异常时，插件不会把原始 JSON 或提示词发进群；缺失的用户回复会使用短安全回退文本。
- 单个窗口的回归模型调用失败后会记录日志并停止自动重试，避免故障期间反复产生模型费用。
- 回归消息最终发送失败会标记失败并记录日志，不会放出原始模型协议内容。
